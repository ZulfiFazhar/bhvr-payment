# Payment Gateway — N-Layer Architecture Scaffold

## Overview

Scaffold payment-gateway project dengan n-layer architecture. Satu project Vite + Hono on Cloudflare Workers, logic frontend dan backend terpisah di folder level.

**Stack:**
- Backend: Hono (CF Workers), 4-layer architecture
- Frontend: React 19 SPA + Hono SSR shell
- Routing: TanStack Router (file-based)
- State: TanStack Query (server state) + Zustand (client state)
- Validation: Valibot (shared between server & client)
- UI: shadcn/ui + Tailwind v4
- Deploy: Cloudflare Workers

## 2. Backend Architecture (4-Layer)

### Request Flow

```
HTTP Request → Route → Controller → Service → Repository → Data Store
```

### Layer Responsibilities

| Layer | Responsibility | Imports From |
|-------|---------------|-------------|
| **Route** | Mount path + HTTP method, bind controller | Controller |
| **Controller** | Parse request (body, params, query), validate via Valibot, return response, handle HTTP errors | Service, shared schemas |
| **Service** | Pure business logic. No HTTP awareness. Throw domain errors. | Repository |
| **Repository** | Data access abstraction. Interface-based for data store swappability. | Data store driver |

### Dependency Rule

Layer atas boleh import layer bawah, tidak sebaliknya. Service tidak import Controller. Repository tidak import Service.

### Error Handling

`middleware/error-handler.ts` di level Route catch semua error, map ke HTTP response format `ApiError`.

### Hono Env

`c.env` (CloudflareBindings) di-pass dari Route ke Controller. Controller extract yang dibutuhkan, pass ke Service/Repository sebagai parameter biasa — tidak leak Hono context ke business logic.

### Example Flow

```
POST /api/payments
  → payment.route.ts (app.post('/payments', paymentController.create))
    → payment.controller.ts (parse body, validate, call service)
      → payment.service.ts (business rules, call repo)
        → payment.repository.ts (save to DB)
```

## 3. Frontend Architecture

### Stack

React 19 + TanStack Router (file-based) + TanStack Query + Zustand + shadcn/ui + Tailwind v4

### SSR Shell

Hono `renderer.tsx` render HTML shell minimal:
- `<head>`: meta tags, CSS link, Vite client
- `<body>`: `<div id="root">` + script tag pointing to React entry
- React mounts/hydrates ke `#root` di client

### TanStack Router (File-Based)

- `@tanstack/react-router` + `@tanstack/router-plugin/vite` for auto route tree generation
- Routes in `src/client/routes/`
- `__root.tsx` = root layout (wraps all pages with providers, navbar, footer)
- Convention: `index.tsx` = `/`, `about.tsx` = `/about`, `$id.tsx` = dynamic param

### Data Fetching

- TanStack Query for all API calls
- Simple fetch wrapper in `src/client/lib/api.ts`
- Query keys and hooks in `src/client/hooks/`

### State Management

- Server state: TanStack Query (caching, refetch, optimistic updates)
- Client state: Zustand (UI state — modals, preferences, etc.)
- Stores in `src/client/stores/`

### Dual JSX Runtime

Satu project, 2 JSX runtime:
- `tsconfig.json`: `jsxImportSource: "hono/jsx"` (server files)
- `tsconfig.app.json`: `jsxImportSource: "react"` (client files)
- Vite plugin `@vitejs/plugin-react` handles React JSX for client files

## 4. Shared Layer & Validation

### `src/shared/` Rules

- Importable by both server and client
- MUST NOT import from `server/` or `client/`

### Valibot Schemas

```
shared/
├── schemas/
│   ├── common.schema.ts   # PaginationSchema, IdSchema, etc.
│   └── payment.schema.ts  # CreatePaymentSchema, PaymentResponseSchema (example)
└── types/
    └── api.ts             # API response wrapper types
```

- Backend controller validates request body/params via schema
- Frontend forms validate input via same schema
- Types inferred from schemas: `type CreatePayment = InferOutput<typeof CreatePaymentSchema>`
- Single source of truth — change schema, both sides update

### API Contract Types

```ts
type ApiResponse<T> = { success: true; data: T }
type ApiError = { success: false; error: string; details?: unknown }
```

## 5. Build & Deploy

### Single Deploy Target

Cloudflare Workers via `wrangler deploy`.

### Vite Build

- Server: Hono app becomes Workers entry point (`src/index.tsx`)
- Client: React SPA bundled as static assets
- `@cloudflare/vite-plugin` handles both — server build + client assets

### Dev

- `vite dev` runs local Workers runtime (Miniflare) + HMR for client
- API routes (`/api/*`) handled by Hono server
- SPA routes (everything except `/api/*`) serve HTML shell, React router handles client-side routing

### Routing Strategy (Server)

```ts
// API routes
app.route('/api', apiRoutes)

// SPA fallback — all non-API requests serve HTML shell
app.get('*', (c) => c.render(<SpaShell />))
```

### Environment

- `wrangler.jsonc` defines bindings (D1, KV, etc. — TBD)
- Type-safe bindings via `cf-typegen` script
